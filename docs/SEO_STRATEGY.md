Analysis only — no redirects have been created and no live URLs have changed.
Generated by `migration/scripts/seo_url_mapper.py` from the SQL dump plus a
handful of live spot-checks against wholesalebeautyhub.co.uk (listed below,
2026-08-07). Reports live in `reports/` (safe to commit — titles and URLs
only, no customer data).

## How old URLs were confirmed

`permalink_structure`, `woocommerce_permalinks`, `woocommerce_shop_page_id`,
`page_for_posts`, and `page_on_front` in `wp_options` gave the configured
patterns. Rather than trust configuration alone, four representative live
pages were fetched and checked against those patterns:

| URL fetched | Confirmed |
|---|---|
| `/shop/vee-beauty-second-skin-foundation/` | Product base is `/shop/`, not the WooCommerce default `/product/` |
| `/product-category/face/` | Category base `/product-category/` |
| `/brand/amlactin/` | Brand base `/brand/` (not in `wp_options` — plugin default, confirmed live) |
| `/wbh-beauty-blog/` | Blog index lists posts at flat `/{slug}/`, not nested under the index |

**Correction found in-flight**: the DB shows "Refund and Returns Policy"
as a child of "Terms and Condition" (`post_parent` set), which would
normally produce `/wholesalebeautyhub-2/refund_returns/`. The live page
actually resolves at the flat `/refund_returns/` — WooCommerce registers
its core policy pages by option ID, not by page hierarchy, so the DB's
parent/child relationship isn't what's actually rendered. `seo_url_mapper.py`
treats all pages as flat (`/{slug}/`); trust the observed behaviour, not the
schema, when they disagree.

**Canonical domain**: `https://wholesalebeautyhub.co.uk` (non-www). The live
site already 301s `www.` → apex. Keep this when the domain is pointed at
Shopify.

## Findings that need a decision, not just a redirect

1. **One real URL collision**: product category "VALENTINE COMBO DEALS"
   (`/product-category/valentine-combo-deals/`) and brand "VALENTINE COMBO
   DEALS" (`/brand/valentine-combo-deals/`) share a slug. Both would map to
   `/collections/valentine-combo-deals` under the default strategy below.
   **Needs a call in Phase 6**: rename one collection's handle (e.g.
   suffix `-brand`) or merge them. See `reports/duplicate_urls.csv`.

2. **Tags have no Shopify equivalent.** Shopify has no tag-archive page by
   default — `/product-tag/{slug}/` currently falls back to
   `/collections/all` for all 103 tags. That's a safe non-broken landing
   spot but loses the tag-specific listing. If any of these tags actually
   drive meaningful traffic (check Search Console before cutover), build a
   matching collection for it instead of accepting the fallback. ADR-003.

3. **The blog isn't linked from the header mega-menu.** The two blog posts
   and the blog index page don't appear in any of the 157 header nav-menu
   items (confirmed by cross-referencing `wp_posts`/`_menu_item_*` meta
   against blog URLs) or in any other page's body content. Low content
   volume (2 posts) makes this low priority, but worth deciding whether the
   Shopify nav should surface `/blogs/news` given the WordPress one didn't.

4. **"Contact" and "Cookie Policy" pages aren't linked anywhere found** —
   not in the header mega-menu, not in page/product body content, and (per
   a live footer fetch) not in the footer either, unlike the other legal
   pages (see below). Worth a human check on the live site before deciding
   whether these need a redirect target promoted somewhere more visible.

5. **Existing Cookie Policy meta description is wrong on the live site**
   (pre-existing, not caused by this migration): its Rank Math description
   is a verbatim copy of the Terms & Conditions description ("Read the full
   terms and conditions for shopping..."). Worth fixing when copy is
   ported to Shopify rather than carrying the error forward.

## Why the raw "orphan" count looks scary and mostly isn't

A naive "not linked from the nav menu or from any page's body content" check
flags 716 of 875 published URLs. That number is misleading on its own:

- **519 are products.** WooCommerce (like most storefronts) doesn't put
  individual products in the primary nav — they're discovered through
  category/brand archive pages, which *are* in the menu. Not a finding.
- **103 are tags.** Tag archives are essentially never in a nav menu either;
  see finding #2 above for the actual decision this creates.
- **12 are WooCommerce/plugin utility pages** (cart, checkout, my-account,
  wishlist, reviews, receipts, dashboard, buy-again) — always reachable via
  the header cart/account icons on every page, never through content links
  or the nav-menu system. Not orphans.
- **5 are legal/info pages** (About, Privacy Policy, Refund & Returns,
  Terms & Conditions, Shipping Policy) that live in the theme's
  **hardcoded footer**, confirmed by fetching the live homepage. The footer
  isn't built from `wp_nav_menu` data (this site registers exactly one menu
  — the header mega-menu, 157 items, all under Home/Brands/Makeup/
  Skincare/Beauty Tools) so it's invisible to a database-only script. Known
  limitation, not a defect in the data.
- **80 remain genuinely unclassified** and are the ones worth a human look:
  26 categories, 49 brands, the 2 blog posts + blog index, and the 2 pages
  in finding #4. Full detail (with the specific reason for every row) is in
  `reports/orphan_urls.csv`; the 80 that need review carry the reason
  `not_reachable_via_menu_or_content_link`.

The lesson for later phases: this store's navigation is theme/page-builder
driven in several places (footer, WooCommerce account UI), not purely
`wp_nav_menu` data. Phase 6/7 should account for that when rebuilding
Shopify's navigation rather than assuming the WordPress menu is the whole
picture.

## Existing SEO copy worth preserving

Nine pages have manually written Rank Math titles/descriptions (everything
else relies on Rank Math's auto-generated fallback — verified: 0 of 611
products have custom SEO meta, so there's no per-product copy to carry over
beyond the product title/description already in `products.json`). Homepage,
About, Shop, Brands, Contact, Shipping Policy, Privacy Policy, Terms &
Conditions, and Cookie Policy all have hand-written titles/descriptions —
capture these when their content moves to Shopify Pages (Phase 6/7); they
aren't referenced by the current product/customer CSV pipeline since pages
aren't part of Phase 3/4's scope.

## Redirect implementation (for Phase 13, not now)

`reports/redirect_matrix.csv` is already shaped for Shopify's bulk redirect
CSV importer (Admin → Navigation → URL Redirects → Import): the `old_url`
and `new_path` columns map directly to Shopify's `Redirect from`/
`Redirect to`. Import it after the store's products/collections/pages exist
with the handles this report assumes, and after decision #1 above is made
(re-export if a brand handle changes).

## Canonical URL strategy

- Shopify sets canonical tags automatically for products, collections,
  pages, and blog articles, including collapsing `?variant=`-suffixed URLs
  to the base product URL — no manual work needed there.
- Keep the apex domain (`wholesalebeautyhub.co.uk`) as primary in Shopify's
  domain settings to match the redirect matrix and the site's current
  www→apex behaviour.
- Ensure the 301s in the redirect matrix land on Shopify's canonical form
  exactly (no trailing slash — Shopify's own URLs don't use one, matching
  the `new_path` column already).

## XML sitemap strategy

Shopify auto-generates `/sitemap.xml` (with sub-sitemaps per content type)
once products/collections/pages/blog posts exist — no manual sitemap file
is needed or possible to customize beyond what Shopify includes. At cutover:
resubmit `/sitemap.xml` in Google Search Console under the verified property
for this domain; the current Rank Math-generated sitemap becomes irrelevant
automatically once DNS points at Shopify.

## Robots.txt strategy

No custom Rank Math robots.txt override exists on the live site (checked
`wp_options`) — it's using WordPress/WooCommerce defaults, so there's
nothing custom to port. Shopify ships a sensible default `robots.txt.liquid`
(disallows cart/checkout/account, search, etc.) — review it during Phase 7
theme setup but no migration action is required here.

## Structured data recommendations

Shopify's default theme templates already emit Product, BreadcrumbList, and
Organization JSON-LD. Recommendations for Phase 7:
- Verify Product schema includes `sku`, `brand` (mapped from the vendor
  field `csv_generator.py` already populates), `offers.price`, and
  `offers.availability` — all already present in `products.json`.
- Add BreadcrumbList schema reflecting the new `/collections/{slug}` →
  `/products/{slug}` structure once collections are built (Phase 6).
- No FAQ/Review schema was found in the WooCommerce content, so none needs
  preserving.
